# Чек-лист передачи дизайна в разработку

Проходим перед тем, как задача уходит разработчику. Это Definition of Ready для дизайна. Подробности требований — в [стандарте](../STANDARD.md).

Макет передаётся как сценарий, который можно пройти, а не как набор изображений.

## Задача

- [ ] **R2.1** Заполнено [описание решения](../templates/SOLUTION_BRIEF.md): пользователь, ситуация, момент ценности.
- [ ] **R1.1** Для новой механики есть [запись решения](../templates/DECISION_RECORD.md) со сравнением вариантов.
- [ ] **R2.3** Каждое обязательное поле и шаг обоснованы.

## Структура и понятность

- [ ] **R3.1** Главное действие и данные выделены; иерархия совпадает с важностью.
- [ ] **R4.1** Показаны текущее положение, выбор и путь возврата.
- [ ] **R4.2** Названия сверены со словарём продукта; кнопки называют результат.
- [ ] **R4.4** Подписи полей, подсказки формата и тексты ошибок написаны.
- [ ] **R5.1** Каждое модальное окно обосновано; описаны выход и обработка несохранённых данных.
- [ ] **R10.1** Нет дублирующих способов выполнить одну задачу.

## Состояния и крайние случаи

- [ ] **R8.1** Нарисованы загрузка, нет данных, нет совпадений, ошибка, успех, нет доступа, частичный результат.
- [ ] **R6.1** Описано, какие стадии результата различает система и что видит человек на каждой.
- [ ] **R6.2** Для необратимых действий описаны последствия и текст подтверждения.
- [ ] **R8.2** Описано, что сохраняется при ошибке и что можно повторить.
- [ ] **R3.3** Макет показан на реальных данных: длинные названия, пустые и большие списки.

## Система и доступность

- [ ] **R7.1** Использованы компоненты и токены дизайн-системы; новые варианты оформлены записью решения.
- [ ] **R8.3** Описан порядок фокуса и клавиатурное управление для нестандартных элементов.
- [ ] **R8.4** Состояния различимы без цвета; у иконок без подписи есть доступные имена.
- [ ] **R8.5** У перетаскивания есть альтернатива.
- [ ] **R5.3** Для анимаций указано назначение и поведение при уменьшении движения.

## Открытые вопросы

- [ ] Записано, что проверено прототипом, а что остаётся предположением.
- [ ] Записано, что нужно проверить в работающем продукте после реализации.
