# Чек-лист передачи дизайна в разработку

Короткий барьер между дизайном и кодом. Это Definition of Ready. Содержательная проверка решения уже сделана на [дизайн-ревью](DESIGN_REVIEW.md); здесь подтверждаем, что разработке есть с чем работать и додумывать ничего не придётся.

## Решение

- [ ] Дизайн-ревью пройдено с вердиктом «Готово к передаче»; дата и участники указаны на странице «Описание» файла.
- [ ] Открытых находок P0 и P1 нет; P2 и P3 заведены задачами с ID требований.
- [ ] Исключения из обязательных требований оформлены по [шаблону](../templates/EXCEPTION.md).

## Файл

- [ ] Файл соответствует [требованиям к файлу макета](../templates/DESIGN_FILE.md): сценарии, состояния, крайние данные, тексты, аннотации.
- [ ] **R8.1** Для каждого экрана есть все состояния.
- [ ] **R6.1** **R8.3** **R5.3** Аннотации стадий результата, фокуса и анимаций на месте.
- [ ] **R4.2** Финальные тексты в макете, без «текст уточняется».
- [ ] **R7.1** Новые варианты компонентов добавлены в библиотеку.

## Разработка

- [ ] Разработчик прошёл прототип и подтвердил, что описанные состояния и поведение реализуемы.
- [ ] Расхождения с возможностями системы обсуждены и отражены в макете, а не устно.
- [ ] Назначено, кто и когда проводит дизайн-приёмку сборки по [чек-листу выпуска](RELEASE.md).
