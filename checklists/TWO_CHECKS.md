# Две проверки: ИИ и человек

Каждое дизайн-ревью, приёмка сборки и аудит проходят две независимые проверки по одним и тем же критериям. Правила — в [стандарте](../STANDARD.md#две-проверки), здесь — как это делать на практике.

## Зачем две

| | ИИ-проверка | Проверка человеком |
| --- | --- | --- |
| Хорошо ловит | Пропущенные состояния, разнобой в названиях, тексты ошибок и кнопок, контраст, «ручные» цвета и отступы на экранах | Поведение, логику сценария, контекст продукта, то, чего нет на скриншотах |
| Плохо ловит | Клавиатуру, скорость, поведение при сбоях, всё, что не видно на изображениях | Пункты в конце длинного списка, свой собственный продукт, к которому привык |

Вместе они закрывают слабые места друг друга. Поэтому критерии одни и те же: ответы можно сравнить построчно.

## Как устроен пункт

```
R4.4  Подписи полей не исчезают при вводе, формат объяснён заранее, ошибка стоит у своего поля?
      ☐ У каждого поля есть подпись, которая не исчезает при вводе.        Да / Нет
      ☐ Требования к формату видны до ввода.                               Да / Нет
      ☐ Ошибка показана у того поля, к которому относится.                 Да / Нет
      ☐ Ошибка не появляется, пока человек ещё вводит значение.            Да / Нет
```

- Все критерии «да» — пункт **выполнен**. Часть — **частично**. Ни одного — **не выполнен**.
- Пункт не относится к решению — **не применимо**, с объяснением.
- Проверить нечем — **не проверить**. Такой пункт не закрыт: найдите способ его проверить.
- Для «частично» и «не выполнен» указывается серьёзность P0–P3 — что случится с человеком.

## Порядок

### 1. Подготовить материалы

- Описание решения: пользователь, ситуация, момент ценности.
- Прототип ключевого сценария (для человека).
- Скриншоты всех состояний сценария (для ИИ): загрузка, пусто, нет совпадений, ошибка, успех, нет доступа, частичный результат. Для приёмки — скриншоты сборки.
- Тексты аннотаций: стадии сохранения, порядок фокуса, анимации, поведение при закрытии. ИИ не видит слоёв макета — то, что не на картинке, перепишите текстом.

### 2. Проверка человеком

1. Откройте [интерактивный чек-лист](https://claude.ai/artifact/WSYyZYb4m6B61DDmGVyGyw), выберите проверку, заполните продукт и сценарий.
2. Ревьюер проходит прототип сам, автор молчит (R2.6).
3. По каждому пункту отметьте критерии. Подсказка «Как проверить» и тревожный признак — под вопросом.
4. Для находок укажите серьёзность и коротко опишите, что не так и где.

Без интерактивного чек-листа — [рабочий лист](WORKSHEET.md) с теми же критериями.

### 3. ИИ-проверка

Можно до, во время или после проверки человеком — ответы ИИ по пункту всё равно откроются только после ответа человека. Три способа:

| Способ | Как |
| --- | --- |
| **На странице** | Экран «ИИ-проверка»: загрузите скриншоты, добавьте описание и аннотации, нажмите «Запустить ИИ-проверку». Запуск расходует лимит вашего аккаунта Claude. Изображения не сохраняются, в историю попадает только результат |
| **Claude Code** | В репозитории стандарта вызовите `/design-check` и приложите скриншоты или путь к ним. Claude вернёт JSON и отчёт. JSON вставьте на экране «ИИ-проверка» → «Загрузить результат» |
| **Чат Claude** | На экране «ИИ-проверка» нажмите «Скопировать задание для ИИ», вставьте его в чат вместе со скриншотами, а ответ — обратно в поле «Ответ Claude» |

Задание для всех способов одно и то же: его собирает `scripts/build_checklist.py` из `checklist/ai_protocol.toml` и критериев.

### 4. Сверка

После обеих проверок в каждом пункте видно ответ ИИ:

| Что видно | Что делать |
| --- | --- |
| **Совпадает** | Ничего |
| **Расхождение с ИИ** — ИИ нашёл проблему, а человек нет | Перепроверьте критерии, где у ИИ стоит ✕. Если ИИ прав — исправьте свой ответ. Если ошибается — напишите почему в поле под ответом ИИ |
| **ИИ этого не увидел** — проблему нашёл только человек | Ничего, находка остаётся |
| **ИИ не смог проверить** | Ничего, пункт проверен человеком |

Пока есть хотя бы одно расхождение без решения, вердикт — «Сверить с ИИ-проверкой».

### 5. Вердикт и отчёт

Вердикт считается сам по правилам стандарта. «Готово к передаче» и «Можно выпускать» возможны, только когда обе проверки проведены и все расхождения разобраны. Отчёт содержит сверку: сколько совпало, какие находки ИИ отклонены и почему.

## Если ИИ часто ошибается в одном пункте

Отклонённые находки с причинами сохраняются в отчётах. Если по одному пункту ИИ ошибается регулярно, уточните его критерии или протокол в `checklist/ai_protocol.toml` — так проверка становится точнее со временем.
