# Изменения стандарта

Версии по semver: новое обязательное требование или ужесточение — мажорная, новое рекомендованное — минорная, уточнение формулировок — патч.

## Руководство «Как мы делаем экраны» — 4 октября 2026

Стандарт остаётся версии 3.0.0: требования не менялись.

- `guides/SCREENS.md` — приёмы, проверенные на burabay-gis: работа по образцам и видео, варианты спорных экранов, проверка глазами на телефоне и десктопе; движение на Motion; меню разделов как в мобильном Claude, листы снизу, капсулы; карта как Apple Maps на iPhone и Mac; документ отдельным экраном; тёмная тема как в macOS; таблица ошибок и список проверки перед сдачей.
- Скилл `design-make` ссылается на руководство.

## 3.0.0 — 3 октября 2026

Без признаков ИИ-дизайна. Повод — первый прогон ИИ-дизайнера: канбан-доска с подписями-инструкциями под колонками, «Просрочено · 30 сен», текстами в пустых состояниях и строкой фильтров с крестиками. Команда назвала это «стиль ИИшки».

- Список признаков ИИ-дизайна `checklists/AI_TELLS.md`: И1–И42 в девяти группах — текст вместо формы, лишние элементы, цвет, шрифт, компоненты, шаблонная обвязка, раскладка, движение, выдуманное содержимое. Собран по скиллам Anthropic, Impeccable, taste-skill, avoid-ai-design, ux-skill и публикациям практиков.
- Новые обязательные требования: R4.8 — продукт объясняет себя формой, а не поясняющим текстом (Рамс 4, HIG Writing); R7.6 — нет признаков ИИ-дизайна, если выбор не задан дизайн-системой или не записан с причиной (Рамс 7). Всего 54 требования: М — 27, М+Р — 23, Р — 4.
- R10.1 ужесточено: нет отдельных элементов для действия, которое уже выполняет сам элемент управления.
- Критерии уточнены: пустое состояние показывает, как начать, только если это не видно на экране (R8.1); применённый фильтр может быть виден на самом элементе управления (R4.3).
- Протокол ИИ-проверки: признаки ИИ-дизайна — находки, а не достоинства.
- Скилл `design-make` для Claude Code: проектирование по стандарту с самопроверкой по списку признаков и через `design-check`.
- В описании решения — раздел «Визуальное направление».
- R4.8 входит в быструю проверку: 15 пунктов.

## 2.0.0 — 2 октября 2026

Три источника на равных и две проверки по одним критериям.

- Стандарт опирается на Рамса, Айва и Apple HIG явно: раздел «Три источника», у каждого требования указаны основания, карта источников `checklists/SOURCES.md` собирается автоматически.
- Новые обязательные требования: R2.6 — прохождение сценария без объяснений автора (Айв); R4.7 — понятные сообщения об ошибках (Айв, HIG Writing); R8.8 — все состояния элементов управления и область нажатия (HIG Buttons, WCAG); R8.9 — несохранённые изменения не теряются молча (HIG Modality). Всего 52 требования: М — 25, М+Р — 23, Р — 4.
- Раздел «Две проверки»: ИИ-проверка и проверка человеком обязательны для дизайн-ревью, приёмки и аудита; человек отвечает первым; находки ИИ подтверждаются или отклоняются с причиной; «Готово» — только после обеих.
- У каждого требования 2–7 критериев «да/нет» для продукта и отдельно для макета; итог пункта считается по критериям.
- Протокол ИИ-проверки `checklist/ai_protocol.toml`, скилл `design-check` для Claude Code, инструкция `checklists/TWO_CHECKS.md`.
- Интерактивный чек-лист: критерии вместо общей оценки, запуск ИИ-проверки по скриншотам прямо на странице или загрузка ответа Claude, сверка, вердикт с учётом обеих проверок.

## Чек-лист для людей — 2 октября 2026

Стандарт остаётся версии 1.1.0: требования не менялись, добавлены инструменты для самостоятельной проверки.

- Интерактивный чек-лист (`site/checklist.html`, опубликован на claude.ai): четыре режима — дизайн-ревью, быстрая проверка, приёмка сборки, аудит; вердикт по правилам стандарта, отчёт в Markdown, копирование находки как задачи, общая история проверок команды.
- Рабочий лист `checklists/WORKSHEET.md` для чтения и печати.
- Человеческий слой `checklist/items.toml`: для каждого требования вопрос, способ проверки, тревожный признак, порядок прохождения; отдельные вопросы для макета.
- Сборка `scripts/build_checklist.py` сверяет чек-лист со `STANDARD.md`; CI проверяет, что собранные файлы актуальны.

## 1.1.0 — 2 октября 2026

Процесс перестроен под design-first. Формулировки и уровни требований не изменились.

- У каждого требования появился этап проверки: М — макет (23), М+Р — проектируется в макете, проверяется в реализации (21), Р — только реализация (4).
- Новый главный чек-лист: дизайн-ревью (`checklists/DESIGN_REVIEW.md`) с вердиктом «Готово к передаче / Доработать / Вернуться к задаче».
- Требования к файлу макета (`templates/DESIGN_FILE.md`): структура страниц, обязательные состояния, аннотации, работа с токенами и библиотекой.
- Чек-лист передачи сокращён до барьера готовности; чек-лист выпуска стал дизайн-приёмкой сборки против макета.
- Исправления по итогам аудита проходят через макет и дизайн-ревью.

## 1.0.0 — 2 октября 2026

- Первая версия стандарта на основе десяти принципов Дитера Рамса: 48 требований R1.1–R10.4.
- Шкала серьёзности P0–P3 и три уровня качества продукта.
- Чек-листы аудита, передачи в разработку и выпуска.
- Шаблоны описания решения, записи решения, исключения и отчёта аудита; шаблоны PR и issue для репозиториев продуктов.
- База знаний: руководства по принципам Рамса, Apple HIG и подходу Джони Айва (источники проверены 1 октября 2026).
