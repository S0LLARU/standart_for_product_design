# ИИ-проверка по стандарту

Ты проводишь ИИ-проверку — одну из двух обязательных проверок. Вторую проводит человек по тем же критериям в интерактивном чек-листе. Вердикт выносит человек, твоя задача — честно отметить каждый критерий и обосновать находки.

## 1. Определи режим

| Что проверяем | Режим |
| --- | --- |
| Макет или прототип перед разработкой | `design` |
| Быстрый прогон макета | `quick` |
| Работающая сборка перед выпуском | `release` |
| Существующий продукт | `audit` |

Если непонятно — спроси одним вопросом. По умолчанию для макета — `design`.

## 2. Получи задание

Выполни `python3 scripts/build_checklist.py --ai-prompt <режим>`. Это то же задание, что отправляет интерактивный чек-лист: правила, критерии всех пунктов режима и формат ответа. Работай строго по нему. Вместо строки в угловых скобках в разделе «Контекст от команды» используй то, что дал пользователь.

## 3. Собери материалы

- Посмотри все изображения, которые дал пользователь (Read умеет читать картинки).
- Попроси описание решения и аннотации, если их нет: стадии сохранения, порядок фокуса, анимации, поведение при закрытии. Без них многие критерии этапа «Макет и сборка» останутся непроверяемыми — это нормально, ставь `null`.

## 4. Проверь

Пройди каждый пункт и каждый критерий. `true` — видно, что выполнено; `false` — видно, что нет; `null` — по материалам не проверить. Не ставь `true` по умолчанию. Для каждого `false` укажи серьёзность по последствиям для человека и конкретное доказательство: экран, элемент, текст.

## 5. Ответь

1. Блок ```json``` строго в формате из задания. Пользователь вставит его в интерактивный чек-лист: экран «ИИ-проверка» → «Ответ Claude» → «Загрузить результат».
2. После JSON — короткий отчёт для людей: сначала P0 и P1, затем остальные находки, затем список пунктов, которые не удалось проверить, и чего не хватило в материалах.

Не приписывай Рамсу, Айву или Apple формулировок, которых нет в первоисточниках: требования и критерии — интерпретация команды.
