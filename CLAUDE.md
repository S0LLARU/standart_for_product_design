# Инструкции для Claude

Этот репозиторий — стандарт дизайна продуктов команды. Основа — десять принципов Дитера Рамса; требования в `STANDARD.md` имеют ID вида `R6.1`.

## Аудит и ревью дизайна

Когда просят проверить продукт, макет, скриншот, PR или сценарий:

1. Работай по `checklists/AUDIT.md`. Для PR — по `checklists/RELEASE.md`, для макета перед разработкой — по `checklists/HANDOFF.md`.
2. Каждую находку привязывай к ID требования и серьёзности P0–P3 из `STANDARD.md`. Серьёзность определяй по последствиям для человека, а не по типу требования.
3. Указывай доказательство: что именно видно или воспроизводится. Если по имеющимся материалам пункт проверить нельзя (например, клавиатуру по скриншоту), отмечай его как непроверенный, а не как выполненный.
4. Начинай отчёт с P0 и P1. Визуальная полировка не должна заслонять потерю данных или нечестную обратную связь.
5. Оформляй результат по `templates/AUDIT_REPORT.md`, находки — по `templates/github/ISSUE_TEMPLATE/audit-finding.md`.
6. Не предлагай упрощение, которое переносит сложность в память человека (R10.2), и не оправдывай решение словами «так минималистичнее».

## Редактирование документов

- Принципы принадлежат Рамсу; требования, примеры и методы — наша интерпретация. Не приписывай Рамсу, Айву или Apple формулировки, которых нет в первоисточниках.
- Держи различие между пересказом источника и применением командой, как это сделано в `principles/`.
- Новое требование: ID в разделе своего принципа, уровень О или Р, способ проверки. Добавь пункт в `checklists/AUDIT.md` и, если применимо, в `HANDOFF.md` или `RELEASE.md`.
- Любое изменение `STANDARD.md` сопровождается записью в `CHANGELOG.md` и повышением версии по правилам из файла.
- Пиши по-русски, ясными короткими предложениями, в стиле существующих документов.
